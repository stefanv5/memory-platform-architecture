10能力补齐·机制级:缺的是什么、上游怎么带、我们在哪一步接

缺失类型三分类:【源缺失】=数据从未被生产(要补"生产线") · 【未实现】=代码/入口不存在(要写) · 【难复用】=上游代码在但不能直接用(说明为什么)。每项四问:缺什么→上游怎么带→流程哪一步接(★标记,见图 7/图 8)→怎么算完成。

C1 · temporal 时间臂【未实现 + 难复用(思路可复用,形态须按产品合同重写)】

缺什么:数据现成(四时间列已在 QP01 通路);缺窗口来源与参数通道。上游怎么带:HTTP body 可选 TemporalWindow{start,end}(tz-aware),docstring 原话是"时序臂的检索窗口/加分",不是硬过滤器;SQL 对 occurred/mentioned 加谓词+沿边 spreading。计划怎么带:★C1 两处(图 8)——步 8 解封参数(键集+白名单+DTO 双端 bump),步 19 例程加窗谓词;或更省:步 20 后做 Python 侧 boost(不触 SQL)。怎么算完成:T11 新时间 gold。

C2 · graph 图臂【源缺失(主体)+ 未实现(计算件)+ 难复用(逻辑可复用,例程形态不可)】

缺什么信息:三类行——entities 行(canonical_name/bank_id/mention_count…)、unit_entities 关联(unit↔entity)、memory_links 语义边(weight=cosine 相似度本体)。上游怎么带(原文→行):原文→LLM 抽取(每 fact 已输出 entities:list[str])→ 名字规范化/去重(纯文本)→ pg_trigram+共现+recency 解析(不是 LLM)→ 事务外 INSERT entities 行 → 写事务内 unit_entities+共现行;边=retain 期对全库 ANN(top50·≥0.7)+批内 numpy 合并;删除后维护期 relink_pass 补边(队列驱动,非定时)。计划怎么带:★注入 1-3(图 7)+★C2 读侧第三臂(图 8);合同解封四处;ENTITY/EDGE release 校验已在。无需新增模型 purpose(trigram 纯文本方案)。怎么算完成:实体 oracle(全新造,现空白)+T11。

C3 · 中文 keyword【难复用(上游可配是运行期;产品 generated 列编译期封存)】

上游怎么带:bm25_language 配置→写列与查询同语言,切语言只影响新行。计划怎么带:三方案——①换 regconfig(生成列变更=新 pair;不重嵌,存量从 OBS 重投影);②pgroonga 后端(新写分支+索引+扩展依赖,改动面最大);③维持 english+声明限制。怎么算完成:AT05c/AT11c 中文 gold+口径入合同。
