## 1. 演化分级框架：先定义"变"的深度

"数据活起来"不是二值命题。按 **触发器（什么让它变）→ 执行者（谁来做这个变）→ 守护（怎么防止变坏）** 三个轴，可分五级：

| 级别 | 名称 | 触发器 | 执行者 | 守护 | 典型例子 |
|---|---|---|---|---|---|
| **L0** | 静态冻结 | 无 | — | — | 朴素向量库/RAG：写入即终点 |
| **L1** | 规则维护 | 事件/周期（确定性） | 确定性代码 | 幂等/测试 | 去重、TTL、索引修复、遗忘曲线 |
| **L2** | 语义重组 | 固定管线触发 | LLM（固定 prompt/管线） | 审计/校验 | 巩固、摘要重写、块级文档刷新 |
| **L3** | 反馈优化 | **使用/结果数据回流** | 权重更新/策略调整 | 统计/评估 | 命中率加权、重要性学习、RL 策略 |
| **L4** | 参数进化 | 高频知识确认 | 蒸馏/微调/KV-cache | 版本化回滚 | 技能写进 adapter/权重 |
| **L5** | 系统自改造 | 评估结果 | 系统改自己的策略/配置 | judge 回归守护 | 治理策略 A/B 自进化 |

**关键判别式**：L1/L2 的变化是"**管线决定的**"（数据只是被动输入）；L3 的变化是"**数据决定的**"（使用数据改变处理方式）；L5 才是 RSI 的本义（递归：系统改进改进系统的方法本身）。

## 2. 六产品逐家调研

### 2.1 Hindsight —— L2 强实现，L3 缺失（代码级确认）

**沉淀后数据会变吗？会，且是全赛道机制最完整的 L2。**`[代码]`

| 变化 | 触发器 | 执行者 | 守护 |
|---|---|---|---|
| facts → observations（巩固） | retain 后 / 删除失效后 / 手动 / 每 300s 对账兜底 | LLM 固定管线（8 条成文方针） | 强制 reason 审计、0.97 去重仲裁、单调时间界 |
| observation 失效 | 源事实被 invalidate | 撤回检测 + 专门 "unsay" pass | 区分"断链"与"真撤回"；失效单元归档不销毁 |
| mental models 重写 | watermark 陈旧 + cron | reflect agent，**块级 delta 操作** | 两层校验；不变式"只会变好或不变"；未提及块逐字保留 |
| 链路图自愈 | graph_maintenance 队列 | 确定性代码（补链/剪枝） | wall-clock 预算化、可恢复 |

**有 L3 吗？没有——这是代码级结论。**自适应 recall 预算是运维配置的固定比例（`_resolve_thinking_budget`），不是学习出来的；巩固优先级、保留策略都是显式配置；**没有任何"recall 命中→处理方式改变"的回路**。全系统没有 feedback 表、没有 use_count 字段、没有基于使用的重要性评分。

**评级**：L2（强）。上一轮 R7 ◐ 维持不变——它做到了"数据自洽"（一致、可溯源、自动保鲜），但做不到"数据自适应"。

### 2.2 Zep / Graphiti —— 唯一有"真算法"自组织的产品（评级上调）

**沉淀后数据会变吗？会，而且是三条独立进化线的组合。**`[官方]``[搜索]`

| 变化 | 触发器 | 执行者 | 算法含量 |
|---|---|---|---|
| **边失效** | 新三元组与旧边矛盾 | LLM 逐对矛盾检测 → 旧边打 `invalid_at` 时间戳（**不删除**） | 双时态模型：`[t_valid, t_invalid]` + `[t_created, t_expired]`，支持"系统在时刻 X 知道什么"与"世界在时刻 X 是什么"两种查询 |
| **实体摘要进化** | 实体的 fact 数过阈值 | LLM 滚动压缩 `entity_summary` | 累积式摘要，原始事实保留在边上 |
| **图自组织** | 周期性（非每次摄入） | **Leiden 社区检测**（graspologic），分层 3 级，每社区 LLM 摘要 | 真图算法，非纯 LLM；论文数据：每社区更新中位耗时 ~1.7%，1 万节点全量建社区 ~5.3 分钟 |

**这是六家中唯一把"确定性图算法 + LLM 语义重组"组合起来的**：Leiden 负责结构重组（哪些实体该聚类），LLM 负责语义压缩（聚类意味着什么）。延迟数据：LongMemEval 从 7,610ms 降到 719ms（-90%）。

**有 L3 吗？没有**——社区重建是周期性的，不感知使用反馈。

**评级修正**：上轮 R7 ◐ → **●（自组织维度）**。它的"数据活"体现在结构会重排、事实会失效但历史可查询——是 L2 里算法含量最高的实现。

### 2.3 Cognee —— 唯一有产品化"反馈加权"的竞品（评级上调，重点修正）

**沉淀后数据会变吗？会，且有一条 L3 级回路。**`[官方]`（docs.cognee.ai/core-concepts/data-flows）

三条管线的进化语义（本次调研的核心新发现）：

1. **Session learning 管线**：`remember(data, session_id)` 只写快速会话缓存（"raw and fast — no chunking, no graph extraction"）；后台自动（`self_improvement=True` 默认开启）或显式 `improve(session_ids)` 触发蒸馏——把"被门控接受的会话指导"固化为 **curated lesson documents**，把会话 Q&A 和 agent 轨迹持久化进图，并**应用反馈权重：对好答案有贡献的图元素，在未来检索中获得更高影响力**。
2. **Self-improvement 管线**：`improve(dataset)` 原地增强永久图——添加三元组索引、数据集级 bucket/root 摘要等派生检索结构；同时把新图关系**回写**到会话缓存，实现会话↔图双向上下文交换。
3. **Ingestion 管线**：无 session_id 的 `remember` 走完整 ECL（chunk→实体关系抽取→向量索引→溯源）。

**这意味着 Cognee 是六家中唯一产品化了"使用结果改变检索行为"的**（答案评分 → 图元素权重 → 未来召回排序）。虽然反馈信号的来源（谁给答案评分、门控规则是什么）文档披露有限，权重算法细节未知，但机制存在且默认开启。

**评级修正**：上轮 R7 ◐ → **●（L3-lite）**。诚实标注：权重机制的自反馈强度、是否有评估器守护变化，公开资料不足以判定。

### 2.4 Letta —— 唯一产品化"预测性重组"的竞品（评级上调，重点补充）

**沉淀后数据会变吗？会，由一个后台 agent 预测性地重排。**`[论文]`（arXiv:2504.13171）

- **Sleep-time compute**（Letta/Princeton/Berkeley，2025-04）：LLM 系统大部分时间离线——利用这段空闲，**sleep-time agent 预判未来可能的查询，提前重组记忆**，把"有用的中间推理和隐含信息"显式化为精炼文本笔记（非向量），测试时前置于查询。
- **量化收益**：SWE-bench +18%（sleep-time agent 从代码库归纳最佳实践）；电商推荐 5×；**给定准确率下总计算量反而下降**（把工作从测试时挪到离线）。
- **产品化**：Letta v0.11.0 起支持 async sleep-time agents——后台 agent 与主 agent 通过共享 memory blocks 连接，自主重写 system prompt / 记忆块 / 归档层。官方口径："agents that organize their own memory while you sleep"。

**有 L3 吗？间接有**——重组是预测驱动的（什么查询可能来），不是结果反馈驱动的（上次答得怎样）。且重组者是自主 agent，**风险与 Letta 的定位一致：一个后台 agent 改错记忆块，主 agent 的行为跟着错**——没有评估器守护的披露。

**评级修正**：上轮 R7 ◐ → **●（L2.5 预测性重组）**。

### 2.5 MemOS —— 宣称最激进（L4），公开机制最少

**沉淀后数据会变吗？宣称会一路变到模型参数里。**`[官方]``[搜索]`

- **分层自动晋升**：L1 traces → L2 policies（技能结晶：从轨迹蒸馏可复用技能，Voyager 谱系）→ L3 world models → crystallized Skills。向上是巩固/抽象，**向下 L3 先验反过来指导记录什么、激活哪些技能**（双向）。
- **Procedural memory**：技能/工具/代码作为可执行程序性知识"积累"——官方明说对标 Voyager skill library。
- **MemOS Replay**：记录可重放的执行轨迹（时间旅行调试/A/B/审计）——为进化提供审计基础。
- **MemGovernor**：权限/合规/审计/隔离 + 遗忘与用户记忆隔离（beta）——治理层存在。
- **L4 参数化**：论文主张明文→激活（KV-cache）→参数（LoRA）的迁移融合；高频技能可结晶进模型。

**关键缺口**：L1→L4 晋升的**具体算法没有公开文档**（crystallization 的触发条件、频率统计方法、质量门控全部未知）；"self-evolving" 是定位声明而非可复现的机制描述。论文的参数迁移（明文↔KV-cache↔LoRA）是研究主张，产品落地度无法从公开资料验证。

**评级**：维持上轮 ●（宣称维度）/ 验证存疑。分级：宣称 L4，可验证证据到 L2。

### 2.6 Mem0 —— 写时演化，沉淀后基本冻结

**沉淀后数据会变吗？只在写入时变。**`[论文]`

每次新交互触发对既有记忆的 ADD/UPDATE/DELETE 决策（LLM 判断新旧关系）——这是**写时演化**（新数据驱动对旧数据的改写），沉淀之后如果没有新数据到来，记忆就是静态的。无后台重组、无使用反馈、无周期性治理。对话语料持续流入时它表现为 L2-；数据稀疏时退化为 L0。

**评级**：维持 ○/◐ 边界。

## 3. 学术界的自进化算法盘点（可直接移植的算法菜单）

这是回答你第三个问题——"有没有自进化的算法"——的核心：**算法在学术界是存在的、具体的、可移植的**，产品界只是还没把它们组装完整。

| 算法系统 | 进化机制 | 触发器 | 复杂度 | 对 contextDB 的可移植性 |
|---|---|---|---|---|
| **Generative Agents**（arXiv:2304.03442） | 检索分 = recency×importance×relevance；**importance 由 LLM 打 1-10 分**（"刷牙=1，分手=10"）；**累计重要性过阈值 → 反思**：从记忆合成高层推论，反思可递归建立在反思上（记忆树：叶子=观察，枝干=抽象思想） | 阈值（重要性累计） | 低（3 个 prompt） | **极高**——"何时值得进化"的触发器设计，直接可抄 |
| **A-MEM**（arXiv:2502.12110） | **笔记进化**：新记忆入网 → 找 top-k=10 语义邻居 → 每个邻居"自主决定"是否更新自己的描述/关键词/标签/链接 → 可能生成新想法。网络自组织而非静态存储 | 写入事件 | 中（k 邻居 × LLM 决策） | 高——组织知识图谱的自组织写入策略，LoCoMo 上宣称超 Zep/Mem0 最多 30% |
| **AWM**（arXiv:2409.07429） | **在线工作流归纳**：从成功轨迹中 LLM 归纳可复用工作流（如 `add_to_cart(qty, item)`），带质量过滤（语义+抽象匹配），**边干边归纳**（非离线批处理） | 任务成功事件 | 中 | **极高**——你的 skills 层的蒸馏算法，WebArena 相对 +24.6% |
| **ExpeL**（arXiv:2308.10144） | **对比归纳**：LLM 对比成败轨迹对 → 提取可泛化洞见 → 洞见池动态增删改（矛盾即删）；HotpotQA 27%→68%；**洞见池跨任务/跨模型迁移**（GPT-3.5 学的 GPT-4 也能用） | 轨迹对可用 | 中 | 高——团队级"经验→规则"的算法，且可迁移意味着一次学习多处复用 |
| **Mem-α**（arXiv:2509.25911） | **RL 训练记忆管理器本身**（GRPO）：策略模型输出 write/update/delete 操作，奖励 = 构建的记忆带来的回答质量；仅 ~3,700 样本训练即显著超基线，OOD 泛化强；**训练过的记忆管理器能让未训练的 agent 变强** | 训练阶段（离线）→ 推理时策略 | 高（RL 训练管线） | 远期——这是"改进改进系统的方法"（真 L5 方向），但需要奖励信号基建 |
| **MEM1**（arXiv:2506.15841） | RL 学会每轮把记忆**压缩成紧凑内部状态**，丢弃无关历史，内存恒定 | 每轮 | 高 | 低（面向单体 agent 上下文，非组织库） |
| **MemoryBank**（arXiv:2305.10250） | **艾宾浩斯遗忘曲线**：记忆强度随时间衰减，不被强化则淡忘（"Silicon Clock"） | 时间 | 极低（一个衰减函数） | 高——组织知识的自然衰减层，防止死知识淹没活知识 |
| **Memp**（arXiv:2508.06433） | 程序性记忆：Explore → 归纳 → 技能库；检索 → 执行；**跨模型可迁移** | 任务周期 | 中 | 中——skills 层的另一种实现 |
| **Reflexion**（arXiv:2303.11366） | 失败后自我反思，verbal-RL：反思存入情景记忆作为高层反馈 | 失败事件 | 低 | 中——agent 层机制，库层可借鉴为"失败会话的定向蒸馏" |
| **SEMemory**（arXiv:2508.03333） | 框架级：记忆的 Organizing/Utilizing/Refining 三元函数**互相进化**；结果已知后给评估反馈 | 结果已知 | 框架 | 概念参考——"三函数互进化"是组织库 RSI 的好骨架 |

**学界趋势**（2025）：管理策略正从"手写 prompt 启发式"转向"RL 学习的策略"（Mem-α/MEM1/MemAgent）——即"元层"本身开始被优化，这正是 RSI 的方向。

## 4. 结论：谁真的有 RSI？

**直接回答你的三个问题：**

1. **沉淀后数据不变吗？**——没有任何一家是纯静态的（L0），但 Mem0 接近（只在写时变）。
2. **还是按规则变？**——所有六家都有 L1/L2（规则维护 + LLM 固定管线重组），Hindsight 是 L2 实现最完整的（巩固学说+撤回+活文档），Zep 是算法含量最高的（Leiden+双时态）。
3. **还是有自进化算法？**——**产品界没有一个完整 L3+L5 闭环**：最接近的是 **Cognee 的反馈加权**（L3-lite，机制存在但细节不透明）和 **Letta 的预测性重组**（L2.5）；宣称最激进的是 **MemOS**（L4 参数化，机制不可验证）；**L5（系统改自己的治理策略）全部缺席**。真正的自进化算法在学术界已经成型（Mem-α 的 RL 管理器、Generative Agents 的反思树、A-MEM 的邻居进化），等待产品化组装。

**一张总表**（★=该级的最好实现）：

| 产品 | L1 规则维护 | L2 语义重组 | L3 反馈优化 | L4 参数进化 | L5 系统自改造 |
|---|---|---|---|---|---|
| Hindsight | ●（对账/自愈） | ★（巩固+撤回+活文档） | ○（代码确认） | ○ | ○ |
| Zep/Graphiti | ● | ●（★ 算法含量：Leiden+双时态） | ○ | ○ | ○ |
| Cognee | ● | ● | ◐★（唯一反馈加权，细节不透明） | ○ | ○ |
| Letta | ● | ●（★ 预测性重组） | ◐（预测驱动非结果驱动） | ○ | ○ |
| MemOS | ● | ● | ？（未披露） | 宣称（机制不可验证） | ○ |
| Mem0 | ◐ | ◐（写时） | ○ | ○ | ○ |

**学界算法**：L3/L5 的算法已存在（Generative Agents 反思树 / Mem-α RL / A-MEM 邻居进化），无产品组装。

## 5. 对 contextDB 的 RSI 算法选型（六环闭环的具体落位）

把 §3 的算法菜单装配进前一篇文档的六环闭环，每环都有可抄的具体算法：

| 环 | 职责 | 抄谁的算法 | 落地形态 |
|---|---|---|---|
| 1 沉淀 | 全量入证据平面 | — | 已有（retain 管线） |
| 2 验证 | 正确性闸门 | Hindsight 证据链 + Zep 双时态失效 | `valid_from/valid_to` + LLM 矛盾检测（`invalidate_edges` 模式） |
| 3 融合 | 去重/合并 | Hindsight 0.97 仲裁 + A-MEM 邻居进化（新知识入网时更新邻居的标签/链接） | 巩固时带邻居更新 pass |
| 4 失效 | 撤回/衰减 | Hindsight unsay pass + **MemoryBank 遗忘曲线** | 撤回传播 + `importance × exp(-Δt/τ)` 衰减层，防死知识淹没 |
| 5 蒸馏 | 知识→技能 | **AWM 在线工作流归纳**（成功轨迹→playbook）+ **ExpeL 对比归纳**（成败轨迹对→洞见）+ **Generative Agents 重要性阈值反思**（何时值得蒸馏的触发器） | skills 管线三件套 |
| 6 自调参 | 使用反馈改变系统 | **Cognee 反馈加权**（答案评分→图元素权重，最小可行 L3）→ 滑窗自适应预算 → **Mem-α 式 RL 管理器**（远期，奖励=回答质量） | feedback API → 权重表 → 调度优先级 → （远期）RL 策略 |

**两条护栏**（没有它们，RSI 会变成递归自毁）：
1. **评估器守护**：每次治理动作（新巩固策略/新技能入库/权重调整）先跑 judge 回归（Hindsight 的 hs_llm_core 模式是现成方法论），不过关不上线——这是 L5 与"乱改"的唯一区别。
2. **晋升权独占**：agent 只能写草稿层/证据层，beliefs/skills 的晋升只属于后台治理管线（防 Letta 式单 agent 污染全组织）。

**分级落地**（修正前篇 P1/P2 的表述）：P1 先抄低复杂度高收益的四个——Generative Agents 阈值反思（触发器）+ AWM 归纳（技能）+ MemoryBank 衰减（防腐）+ Cognee 式反馈加权（L3 最小闭环）；P2 再上评估器守护的策略 A/B（L5 雏形）；L4 参数化（MemOS 方向）放到组织级版本管理成熟之后再考虑。
